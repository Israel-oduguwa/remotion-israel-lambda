# Remotion Social Ad Engine

This project turns AI-generated course ad payloads into clean, dynamic social videos with Remotion.

It is designed for a local-first workflow today and an n8n/API workflow later:

- n8n generates the script, scene copy, asset URLs, and voiceover URL
- Remotion validates the payload with a single schema
- The `SocialAd` composition renders one of three visual families:
  - `proof-driven`
  - `problem-solution`
  - `story/testimonial`

## What Is Included

- One production composition: `SocialAd`
- A single public render schema: `SocialAdSchema`
- Dynamic duration using the actual voiceover length when available
- Always-on captions
- Three sample payloads in [`examples/`](/Users/macbook/Desktop/Upwork/Remotion/examples)
- A local render wrapper script in [`scripts/render-social-ad.mjs`](/Users/macbook/Desktop/Upwork/Remotion/scripts/render-social-ad.mjs)

## Commands

Install dependencies:

```bash
npm install
```

Start Remotion Studio:

```bash
npm run dev
```

Lint and typecheck:

```bash
npm run lint
```

Render a payload from JSON:

```bash
node scripts/render-social-ad.mjs examples/social-ad-proof-driven.json out/proof-driven.mp4
```

Switch payloads to test the other families:

```bash
node scripts/render-social-ad.mjs examples/social-ad-problem-solution.json out/problem-solution.mp4
node scripts/render-social-ad.mjs examples/social-ad-story-testimonial.json out/story-testimonial.mp4
```

## Payload Contract

Core required fields:

- `adId`
- `templateFamily`
- `brandName`
- `ctaLabel`
- `ctaUrl`
- `logoUrl`
- `primaryColor`
- `secondaryColor`
- `voiceoverUrl`
- `scenes`

Standard scene roles:

- `hook`
- `pain`
- `solution`
- `proof`
- `offer`
- `cta`

Each scene should include:

- `id`
- `role`
- `headline`
- `supportingText`
- `mediaUrl`
- optional `mediaType`
- optional `badgeLabel`
- optional `badgeValue`
- optional `captionText`

Optional future-facing fields already reserved:

- `aspectRatio`
- `campaignId`
- `trackingSlug`
- `prefetchedLocalPath`

Captions can be passed in one of two ways:

1. `captions.timed`
   Use this when n8n already has explicit caption timing.
2. `captions.phrases`
   Use this when n8n only has phrase-level copy and Remotion should distribute it across each scene.

If neither is supplied, Remotion derives phrases from each scene’s `captionText`, headline, and supporting copy.

## Timing Behavior

- The composition tries to read the real duration from `voiceoverUrl`
- If that fails, it falls back to `targetDurationSec`
- Scene durations are weighted by role
- The CTA scene gets a fixed minimum tail so the final action is readable
- Scene transitions are family-specific and deterministic

## Asset Expectations

Version 1 is URL-first:

- `logoUrl`, `voiceoverUrl`, and each scene `mediaUrl` are expected to be reachable URLs
- Remote URLs work well with cloud storage, signed links, or CDN links generated by n8n
- `prefetchedLocalPath` is reserved for a future prefetch/cache step without changing the schema

## n8n Migration Path

The next step after local testing is to keep the payload shape unchanged and wrap this renderer in an API or worker:

1. n8n generates the payload JSON
2. n8n stores assets in remote storage
3. The payload is posted to a render service
4. The render service passes the payload into the `SocialAd` composition

That keeps the local test flow and the later API flow on the same contract.
